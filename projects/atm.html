The project

A complete path from
interface to data.

In eight weeks, our four-person team designed, implemented, integrated and documented an educational ATM simulation. The system connects a C++/Qt desktop client to a Node.js/Express REST API, a MySQL database and a three-service Docker Compose environment running on an Ubuntu LTS virtual machine in CSC Pouta.

The simulation supports PIN-based authentication, debit and credit accounts, dual cards, balance queries, withdrawals, deposits, transaction history and timeout behaviour. It is an educational project, not a production banking system.

Course context

Software development
from process to product.

The project was completed for IN00ED14 Software Development Application Project, a 15-credit course taught in Finnish. I received the grade 5.

The course covered requirements, planning, implementation, testing, documentation, version control, object-oriented modelling, graphical applications, database architecture and team communication. Assessment included the working application, schedule, weekly reporting, documentation, final presentation, GitHub activity, instructor observations, peer evaluation and self-evaluation.

That context matters: the project was assessed not only as code, but as a documented group development process with UML-based design, communication and a working system.

Architecture

Several layers.
One user flow.

The interesting part was not one isolated feature. It was getting the layers to agree with each other.

01

Qt desktop client

C++ and Qt Widgets provide the ATM interface, authentication flow, account selection, withdrawals, transaction views and inactivity handling.

02

REST API

Node.js and Express handle authentication, protected operations, business routes and communication between the client and database.

03

Data layer

MySQL stores customers, accounts, cards, relationships, transactions, PIN-attempt tracking and withdrawal-limit data.

04

Deployment

A three-service Docker Compose environment ran the Node.js/Express API, MySQL and Nginx on an Ubuntu LTS virtual machine in CSC Pouta. Nginx acted as the reverse proxy and TLS endpoint for the project domain.

My contribution

Infrastructure-minded
teamwork.

My main responsibilities were the relational database and the deployment environment.

  • Designed the complete MySQL data model, ER diagram, database structure and seed data.
  • Modelled customers, accounts, cards, card-account relationships, transactions and PIN-attempt tracking.
  • Configured the Ubuntu LTS virtual machine, Docker Compose services, Nginx and TLS.
  • Created scripts for service management, health checks and database reset.
  • Supported integration through review, debugging and smaller implementation changes.
  • Documented the system and produced UML and deployment-related material.

The backend components were divided among other team members. On the Qt side, I mainly helped investigate integration and runtime problems rather than owning a frontend component. The team used separate Git branches, Kanban, hour tracking and weekly meetings, with pull requests to the main branch requiring approval from another team member.
